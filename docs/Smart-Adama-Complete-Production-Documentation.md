# 2. Executive Summary

Smart Adama is an enterprise-grade, decoupled AI-powered learning and civic engagement platform designed to digitize, index, and transform the 11-chapter technical framework of the Smart Adama book into an interactive digital ecosystem. The platform bridges municipal smart-city planning with accessible higher-education pedagogy for students, civic planners, researchers, and citizens of Adama City, Ethiopia.

Engineered strictly as an API-first architecture, the platform pairs an autonomous Vue 3 Single Page Application (SPA) with a robust Laravel 13 REST API backend. At its technological core lies a state-of-the-art Retrieval-Augmented Generation (RAG) pipeline executing hybrid search: blending 1024-dimensional dense semantic vectors (Voyage AI / pgvector) with full-text lexical search (PostgreSQL tsvector) via Reciprocal Rank Fusion (RRF, k=60) and chapter-aware contextual weighting. This guarantees that answers generated by the study assistant are mathematically grounded in the manuscript, preventing hallucination and offering precise bibliographic citations.

# 3. Project Overview

The Smart Adama project originated as an initiative to solve a critical information accessibility gap. The Smart Adama manuscript embodies the definitive strategic vision for modernizing Adama into a sustainable, technology-driven metropolis. However, traditional static documents (such as dense PDF volumes) suffer from low engagement, difficult mobile readability, and an inability to deliver on-demand answers to complex technical queries.

- **Core Purpose: ** Digitize and structure the complete 11-chapter Smart Adama manuscript into a structured database hierarchy.
- **Target Audience: ** Undergraduate & graduate students, urban planners, municipal administrators, and citizens.
- **Problem Solved: ** Overcoming static PDF reading friction through interactive chapter assessments, reading progress indicators, and instant AI study dialogues.
- **Scope Boundaries: ** Strictly decoupled SPA-to-REST API architecture; no server-side rendering, Inertia, or monolithic coupling.

# 6. Core Features


## 5.1 Digital Book & Chapter Reader

A specialized reader interface supporting non-linear chapter exploration. Provides markdown rendering with code syntax highlighting, clean typography, responsive sidebar navigation, estimated reading time, and reading progress tracking (0-100%) that syncs continuously to the backend.


## 5.2 Study AI Assistant (Chapter-Aware RAG)

An interactive conversational study assistant integrated directly into the reader and study views. Users can ask questions regarding chapter concepts. The system performs hybrid semantic/lexical vector search over the book chunks, prioritizes the currently active chapter (+0.35 RRF boost), and streams responses in real time using Server-Sent Events (SSE). Each response provides verifiable source citations including chapter title, section title, and cosine similarity scores.


## 5.3 Global AI Assistant

A floating platform assistant accessible from every page (featuring a spinning animated glow ring toggle). Unlike the Study AI, the Global Assistant is non-RAG; it specializes in platform navigation, developer credits, general smart-city inquiries, and technical guidance, operating under a strict rate limit of 20 requests per 5 minutes.


## 5.4 Chapter Assessment & Quiz Engine

Dynamic assessment module featuring multiple choice (single and multiple select) and true/false questions. Submissions are graded server-side against a 70% passing threshold. Detailed answer breakdowns and pedagogical explanations are returned upon submission, and successful completions automatically unlock gamification awards.


## 5.5 Gamification & Activity Streaks

An automated reward engine evaluating 8 distinct badges upon activity triggers (e.g. First Step, Committed Learner, Perfectionist, Week Warrior, Smart Adama Master). Tracks continuous daily activity streaks with automatic reset logic if a day is missed.


## 5.6 Manual Content Authoring Studio

An administrative management console allowing educators and municipal authors to create and edit books, chapters, sections, and subsections within a visual hierarchy tree, featuring rich text editing and instant preview.


## 5.7 Document Ingestion Pipeline & Monitor

A multi-stage document processing pipeline capable of ingesting PDF manuscripts or structured content. Chunks text into ~700 token blocks with 15% overlap, generates 1024-dim embeddings via Voyage AI, and provides real-time SSE progress streaming with pause, resume, cancel, and retry capabilities.


## 5.8 System Health Diagnostics & RAG Debugger

Dedicated diagnostic views for administrators to inspect CPU, memory, Redis cache, PostgreSQL connection, and pgvector extension status, alongside a live RAG search debug utility that displays raw cosine vs lexical ranks.

# 10. Backend Architecture

The backend application is built upon Laravel 13.23.0 running on PHP 8.3.6. It is designed strictly as a stateless JSON REST API. Server rendering engines (Blade views, Inertia) are absent; all endpoints return standardized JSON or SSE streams.


## 9.1 Application Bootstrap & Pipeline (bootstrap/app.php)

Laravel's modern bootstrap configuration registers the following foundational behaviors:

- **Global Routing Prefix: ** All routes defined in routes/api.php automatically inherit the /api/v1 prefix.
- **ForceJsonResponse: ** Prepends App\Http\Middleware\ForceJsonResponse to ensure all responses (including 404, 422, 500) return application/json headers.
- **Named Middleware: ** Aliases 'admin' (EnsureAdmin::class) and 'throttle.chat' (ThrottleChat::class).
- **Unified Exception Handler: ** Catches all unhandled exceptions and routes them through App\Exceptions\Handler::renderApiException for consistent error formatting.

## 9.2 Architectural Design Patterns

- **Service-Controller Separation: ** Controllers contain zero business logic; they handle validation, delegate to domain services, and return JSON resources.
- **Interface-Driven Extensibility: ** AI and RAG subsystems define strict PHP interfaces (LLMGatewayInterface, EmbeddingProviderInterface) bound in AppServiceProvider.
- **Asynchronous Job Delegation: ** Long-running extraction, embedding, and verification processes run asynchronously via Redis queues (ProcessManualIngestionJob).

## 10.2 Vector Storage and pgvector Indexing

Vector dimensions are strictly set to 1024 to match the primary Voyage AI embedding model (voyage-large-2-instruct) and Google Gemini text-embedding-004. Dense vector indexing is implemented using Hierarchical Navigable Small World (HNSW) graphs. Note that parameters m=16 and ef_construction=64 are implicitly inherited from pgvector defaults and are not explicitly configured in the database migrations:


```sql
-- Main vector column and index on content_chunks (migration 2026_08_22_000005)
ALTER TABLE content_chunks ALTER COLUMN embedding TYPE vector(1024);
CREATE INDEX content_chunks_embedding_hnsw_idx
ON content_chunks USING hnsw (embedding vector_cosine_ops);
-- (Implicit pgvector defaults: m=16, ef_construction=64)

-- Dedicated multi-provider embeddings table (migration 2026_09_03_180757)
CREATE TABLE content_chunk_embeddings (
    id UUID PRIMARY KEY,
    chunk_id UUID REFERENCES content_chunks(id) ON DELETE CASCADE,
    provider VARCHAR(50) NOT NULL,
    model VARCHAR(100) NOT NULL,
    dimension INTEGER NOT NULL,
    embedding vector(1024) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(chunk_id, provider, model)
);
CREATE INDEX content_chunk_embeddings_voyage_hnsw_idx
ON content_chunk_embeddings USING hnsw (embedding vector_cosine_ops)
WHERE provider = 'voyage';
```


## 10.3 Full-Text Search Vector (tsvector & GIN)

To enable hybrid lexical retrieval, content_chunks incorporates a generated PostgreSQL tsvector column populated automatically upon insertion and indexed with a Generalized Inverted Index (GIN):

ADD COLUMN search_vector tsvector

# 12. Authentication & Authorization

Smart Adama deploys a sophisticated dual-layer authentication architecture. Rather than forcing a hard dichotomy between Supabase Auth and Laravel Sanctum, the platform bridges them seamlessly through a custom PersonalAccessToken model (app/Models/PersonalAccessToken.php) that decrypts Supabase JWTs, auto-provisions user profiles in PostgreSQL, and authorizes incoming requests without requiring a centralized OAuth server handshake on every call.


## 11.1 The Dual-Layer Authentication Flow

- **Layer 1 — Supabase Client: ** The user interacts with AuthModal.vue. They may authenticate via Phone OTP (SMS), Email Magic Link/OTP, Social OAuth (Google, Facebook, Apple), or Anonymous Guest Sign-in. Supabase issues a standard RS256 JWT access token stored in localStorage ('sa_token').
- **Layer 2 — Axios Request Interceptor: ** Every Axios request sends Authorization: Bearer <token>. In bootstrap/app.php, all protected endpoints pass through auth:sanctum.
- **Layer 3 — JWT Interception & Auto-Provisioning: ** Laravel's Sanctum Guard invokes PersonalAccessToken::findToken($token). The custom implementation checks if the token contains three base64 dot-separated segments. If so, it decodes the JWT payload, verifies expiration (exp claim), and extracts the user identifier (sub, email, or phone).
- **Layer 4 — Database Synchronization: ** If the user record exists in PostgreSQL, it is fetched. If not (first login), the user is instantly auto-provisioned in PostgreSQL with a UUID, status='active', role='learner', and linked to the provider ID. A transient PersonalAccessToken instance is returned to satisfy Sanctum.
- **Layer 5 — Native Sanctum Fallback: ** If the incoming token is not a JWT, PersonalAccessToken falls back to standard Sanctum B-tree token hashing (for users authenticating via traditional POST /api/v1/auth/login).

## 11.2 Role-Based Access Control (RBAC)

Authorization is governed by the EnsureAdmin middleware (app/Http/Middleware/EnsureAdmin.php) and frontend navigation guards (router/index.ts):

- **Role 'learner': ** Standard learner role. Permitted to access learning, chat, quiz, and profile endpoints.
- **Role 'admin': ** Administrative role. Required for all /api/v1/admin/* endpoints and the Vue /admin route hierarchy.
- **Master Admin: ** Master administrator override whitelist hardcoded to ashenafi.deresa.cse@gmail.com. Guaranteed administrative privileges regardless of environment resets.
- **Anonymous Immunity: ** PersonalAccessToken.php:73 strictly forces $user->role = 'learner' for all anonymous sessions, preventing privilege escalation.

## 13.1 Reasoning Sanitization (ReasoningFilter.php)

Modern reasoning models (such as Qwen 2.5/3.8 or DeepSeek) frequently emit internal chain-of-thought blocks enclosed in <think>...</think> tags. Smart Adama's ReasoningFilter strips these tags unconditionally before returning data to the client or persisting messages into the database. In streaming SSE mode, a sliding-window buffer dynamically intercepts opening and closing think tags on the fly without breaking token flow.


# 15. RAG Pipeline

The Retrieval-Augmented Generation pipeline is purpose-built to prevent hallucination by forcing the LLM to answer exclusively from retrieved context chunks. The verified 10-stage execution pipeline operates as follows:


| Pipeline Stage | Implementation & Function |
| --- | --- |
| Stage 1: Document Extraction | Smalot PDF Parser & Spatie PDF-to-Text extract raw text from uploaded manuscript pages. |
| Stage 2: Text Normalization | DocumentNormalizationService strips null bytes, normalizes line breaks, and repairs corrupted section headers. |
| Stage 3: Structure Parsing | BookIngestionService detects Chapter headings (1-11) and sections (e.g. 2.1, 2.2, 2.2.1), preserving 100% of body text. |
| Stage 4: Semantic Chunking | ChunkingService generates content chunks targeting ~700 tokens with 15% overlap, breaking cleanly on sentence boundaries. |
| Stage 5: Vector Embedding | Voyage AI embeds chunks into 1024-dimensional dense vectors using input_type='document'. |
| Stage 6: Vector Storage & GIN | Chunks and vectors are stored in PostgreSQL content_chunks with HNSW index; search_vector tsvector is generated. |
| Stage 7: Query Understanding | QueryUnderstandingService analyzes user input: detects intent, extracts chapter mentions, resolves follow-up pronouns. |
| Stage 8: Hybrid Retrieval | RetrievalService executes parallel semantic cosine search (top 60) and full-text tsvector lexical search (top 60). |
| Stage 9: Reciprocal Rank Fusion | RRF algorithm merges ranks using k=60; adds +0.35 boost for chunks matching the currently active chapter. |
| Stage 10: Grounded Synthesis | PromptBuilderService injects top chunks into the LLM system prompt; LLM streams answer with verifiable citations. |



## 14.1 The Hybrid RRF Ranking Formula

RetrievalService.php implements the following exact SQL ranking formula:


```sql
rrf_score = (
    (CASE WHEN :chapter_id IS NOT NULL AND sec.chapter_id = :chapter_id THEN 0.35 ELSE 0.0 END) +
    (CASE WHEN semantic_rank IS NOT NULL THEN 1.0 / (60 + semantic_rank) ELSE 0 END) +
    (CASE WHEN lexical_rank IS NOT NULL THEN 1.0 / (60 + lexical_rank) ELSE 0 END)
)
```


# 16. Study AI

Study AI (ChatOrchestrator.php) is dedicated to deep learning within the book reader and study workspace. Key operational characteristics include:

- **Session-Bound: ** Requires active session authentication via Sanctum/Supabase. Sessions are stored in chat_sessions and messages in chat_messages.
- **Chapter Awareness: ** When invoked inside Chapter 4 ('Smart Security'), chunks from Chapter 4 receive a +0.35 ranking bonus, ensuring chapter context takes precedence.
- **Streaming SSE: ** Streamed via SSE from POST /api/v1/chat/sessions/{session}/messages. Tokens emit in real time as generated by Gemini/Groq.
- **Source Citations: ** Every assistant message saves referenced chunk IDs and similarity scores into chat_message_sources, rendered as clickable footnote badges.
- **Message Feedback: ** Users can submit thumbs-up or thumbs-down feedback stored in chat_message_feedback for continuous quality monitoring.

# 17. Global AI

The Global Assistant (GlobalChatController.php) serves as the omnipresent concierge across the platform:

- **Omnipresent Access: ** Accessible from any page via the floating navigation toggle button, featuring an animated border glow ring.
- **Non-RAG Architecture: ** Does NOT perform RAG or query book vector chunks. Instead, its system prompt embeds platform knowledge, engineering team credits, and smart-city concepts.
- **Public & Guest Availability: ** Available to both authenticated users and anonymous guests.
- **Rate Limiting: ** Protected by ThrottleChat middleware enforcing a strict quota of 20 requests per 5 minutes per user/IP.

# 18. Quiz System

The assessment module (QuizGradingService.php) evaluates learner comprehension at the conclusion of each chapter:

- **Structure: ** Quizzes belong directly to a chapter (quizzes.chapter_id). Contains questions of type 'single', 'multiple', or 'true_false'.
- **Grading Algorithm: ** Grading occurs strictly server-side. For multiple-select questions, all correct option UUIDs must be chosen with zero incorrect options.
- **Passing Threshold: ** Default passing score is 70% (quizzes.passing_score_pct). Submitting a passing attempt sets quiz_attempts.passed = true.
- **Attempt History: ** quiz_attempt_answers persists chosen option IDs alongside the boolean is_correct flag and question explanation.

# 19. Learning Progress & Gamification

- **Soft Deletion: ** Users and chat sessions implement SoftDeletes, preserving auditing history while restricting client access.
- **Input Sanitization: ** Incoming request data is strictly validated through Laravel FormRequest classes (LoginRequest, RegisterRequest) and DOMPurify on the frontend.

# 27. Performance

- **HNSW Graph Indexing: ** HNSW indexing on vector columns achieves sub-100ms approximate nearest neighbor lookups across content chunks.
- **Vite Chunk Splitting: ** Vite production build applies code splitting, gzip compression, and lazy-loaded route chunking (transformed 2,939 modules in 10.05s).
- **Cold-Start Mitigation: ** Vue client sends a silent pre-warming ping to /api/v1/health upon initialization to wake Render instances before user actions.

# 31. Known Limitations

In accordance with strict production audit standards, the following verified constraints are documented:

- **1. Cloud Free-Tier Spin-Down: ** When running on Render free tiers, the backend spin-down after 15 minutes of inactivity introduces a 30-50 second cold-start delay upon the first user interaction. Mitigated via client pre-warming pings.
- **2. SMS Gateway Configuration: ** SMS one-time password delivery requires an active third-party SMS gateway (e.g. Twilio or MessageBird) configured in the Supabase project dashboard; otherwise fallback to Email Magic Link is required.
- **3. Cross-Lingual Vector Alignment: ** RAG embeddings are currently computed over the English manuscript text. While the interface supports Amharic and Afaan Oromoo, queries in Ethiopian languages are normalized or translated during query understanding.
- **4. Local Testing Database Ownership: ** Running local automated test suites against PostgreSQL requires test database user table-dropping ownership privileges during RefreshDatabase.

# 39. Glossary


| Term | Formal Technical Definition |
| --- | --- |
| RAG (Retrieval-Augmented Generation) | An AI architecture that enhances LLM generation by retrieving relevant verified text passages from an external vector index to ground model responses. |
| pgvector | An open-source PostgreSQL extension enabling vector similarity searches using Euclidean, cosine, or inner-product metrics directly in SQL. |
| HNSW (Hierarchical Navigable Small World) | A graph-based vector index structure delivering logarithmic query time complexity for high-dimensional approximate nearest-neighbor search. |
| RRF (Reciprocal Rank Fusion) | An algorithmic rank-combining technique that scores items based on their reciprocal position in multiple ranked result sets: score = sum(1 / (k + rank)). |
| tsvector & GIN | PostgreSQL native full-text search vector type and Generalized Inverted Index, enabling high-performance keyword queries across documents. |
| TTFT (Time To First Token) | The latency elapsed between initiating an LLM inference request and the arrival of the very first token in the client stream. |
| Reasoning Sanitization | The programmatic stripping of internal model chain-of-thought tokens (e.g. <think>...</think>) before transmitting output to clients. |
| Canonical Chapters | The definitive 11 municipal transformation chapters authorized by the Smart Adama manuscript. |

## 42.5 Malformed UUID Bug & Resolution

During targeted PostgreSQL testing, an unhandled edge-case bug was discovered in the Chat API context validation:

- **Problem: ** Malformed context.chapter_id values in the JSON payload could reach the database layer and cause PostgreSQL to throw a SQLSTATE[22P02] (invalid input syntax for type uuid), resulting in a 500 Internal Server Error rather than a graceful validation response.
- **Resolution: ** Added strict dot-notation UUID validation ('context.chapter_id' => ['nullable', 'uuid']) to SendMessageRequest.php.
This fix successfully changed the malformed-input behavior from an internal database 500 error to a proper 422 Unprocessable Entity request validation.
